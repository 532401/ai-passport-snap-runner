# 响指跃行

AI Passport 上的离线跑酷游戏，使用 240 × 320 竖屏。薄荷色像素精灵在夜景中奔跑，地图向左滚动。复用原 BSP，应用不链接 demo 菜单、页面或视觉外壳。内置 Musopen 公版录音《在山魔王的宫殿里》，用固定音乐关卡驱动地图。无需联网；实体键导航，麦克风瞬态声音触发跳跃。

## 已确认的玩法

- 首次使用：开始页、三次最响响指、确认、三次最轻响指、练习、正式开跑。整个过程中保持手与设备距离一致。
- Max 为三次强响指的**线性峰值幅度最小值**，Min 为三次弱响指幅度的算术平均值。Max/Min 至少为 1.6；拒收削顶及环境过吵的样本。取消或校准失败不会覆盖已有校准。
- Min 到 Max 的对数区间等分成十档。已识别响指低于 Min 按 1 档，达到或超过 Max 按 10 档。声音识别仍受独立噪声门限限制，不是任何轻声都会触发。
- 十档跳高为 18–90 逻辑像素，重力 800 px/s²。无二段跳、无空中指令排队。低跳落地更快，高跳能越过更宽或更高的障碍。不设顶棚或最大力度惩罚。
- 三滴血。撞石块或在坑中落地扣一滴，移除被撞障碍形成安全恢复区域，随后无敌 1.5 秒，避免连续扣血。第三次受伤结束游戏。
- 分数累计地图移动距离，10 像素记为 1 游戏米，速度固定 105 px/s。全曲 154.091 秒，39 个固定起跳点至少相隔 2.5 秒；每个坑／石块的中心在预定起跳后 280 ms 到达角色。按核对后的 4/4 小节第一拍安排，必要时跳过整小节，不必每拍响指；尾声另按 4 个独立重音安排障碍（含最后一下收束重音），最小间隔仍为 2.5 秒。撑到音乐结束即通关。
- 角色附近的收缩标记提示将到的起跳点，进度条显示全曲进度。上下键调音量 0–50，默认 30。练习和校准静音；暂停同时停下音乐与地图，重来同时归零。同一首录音始终使用同一路线。
- 校准和已结束跑局纪录保存到 NVS 命名空间 `snap_runner` 的版本 2 `rhythm_profile`。新麦克风滤波要求重新校准，旧 `profile` 保留但不沿用。NVS 失败显示提示，不自动擦除。

## 音频与任务归属

同一音频任务独占 BSP 录放音及休眠唤醒，每次写入、读取 80 个样本（5 ms）的 16 kHz、16 位单声道音频。4,930,912 字节 PCM 音轨驻留 Flash，仅按小块复制到 RAM；96 kbps MP3 留作参考，不嵌入，也不需要解码器。参见[资源来源与转换](../../assets/README.zh_CN.md#山妖洞穴音乐)。

游戏音量按线性振幅定义：0 静音，30 为 60%，50 为原始振幅，与浏览器播放器一致。应用先换算成 codec-dev 的对数音量曲线再调用 BSP；直接传入 30 会衰减 35 dB，使录音本就很轻的开头几乎听不见。调音量时日志记录游戏值、芯片值及歌曲位置。音量换算不改变 PCM 时序及重拍时间点；修正音量后的实际发声与喇叭反馈仍需真机试听。

为排查无声，音频任务在启用非零音量时回读 ES8311 的时钟、DAC 接口／供电／静音／音量及路由寄存器；播放中每两秒记录 PCM 峰值、已提交样本数、最长 I/O 耗时和剩余栈空间。这些信息用于区分全零数据、传输停顿及芯片设置问题，不能证明模拟扬声器实际发声。寄存器操作只读，失败时报告错误，不用缓存值代替真实读数。

`CONFIG_SNAP_BOOT_AUDIO_PROBE` 默认关闭。诊断构建可启用它，在界面启动前以芯片音量 80 播放两段各 500 ms 的 1 kHz 测试音，依次为单独输出及全双工录放；均复用 BSP，不修改已保存设置。用户在真机听到了两声，证明这两条输出方式可工作，不代表较轻的录音或完整游戏已通过听感验收。

配乐离线通过四阶 1.5 kHz 低通并平滑归一化响度：较轻的开头提升约 16 dB，响亮的尾段适当衰减以保留峰值余量，样本位置和起跳时间不变。校准和游玩的麦克风输入共用四阶 3.2 kHz 高通，减少配乐能量进入响指识别。这不是回声消除，喇叭失真、声学耦合、真人识别准确率与延迟仍需按实际音量、距离和房间测试。检测器保留 800 ms 预热、起音门限、30 ms 瞬态窗口、高频／衰减检查、180 ms 冷却和安静后重新武装；拍手敲击仍可能触发。不保存麦克风录音。

`tools/snap_music_chart.py` 从结合 4/4 乐谱结构核对的逐拍时间表生成固定谱面。[节奏分析](snap-rhythm.zh_CN.md)记录了实测分段速度、半速修正、准确时间点和试听方法。生成及 `--check` 只需要 Python 标准库，绑定 PCM、拍表哈希、JSON 与 C 头文件，拒绝偏离强拍或间距不足的起跳点。

应用任务持有会话、NVS 和 UI，LVGL 操作加 `bsp_lvgl_lock()`，按键回调只入队。正式游戏以已提交音频样本数减去 `CONFIG_SNAP_OUTPUT_DELAY_MS` 推进 10 ms 物理步；默认 90 ms 是 BSP DMA 队列标称容量，尚非测得的扬声器播放时间戳。暂停／恢复更换传输代次，静音并填满输出缓冲，通过 `bsp_audio_discard_input()` 丢弃排队的旧录音，再从暂停位置续播，避免预填等待成为响指输入延迟。录放失败、发声时音频生产停顿超过 40 ms、时钟回退或应用追赶超过 250 ms 会暂停跑局。真实听感相位及全双工稳定性需上板校准。NVS 写入须等待音频任务确认停止；练习使用墙钟。

闲置菜单 60 秒后降低亮度。180 秒后麦克风任务停止 PCM 读取并休眠音频，确认完成后应用关闭绘制，以 100 ms 定时唤醒的浅睡眠周期和 30 ms 按键扫描窗口待机。按下或按住按键唤亮，恢复音频并重新估计环境声。没有为 ADC 按键凭空添加 GPIO 唤醒接口。睡眠／唤醒行为和待机电流仍需实机测量。

## 字体与验证

Noto Sans SC Medium（字重 500）生成 16、22 px 两套 4 bpp 未压缩子集，以常量驻留 Flash。参见[资源说明](../../assets/README.zh_CN.md)和 `tools/snap_fonts.py`。覆盖全部固定界面字符及可打印 ASCII；启动时用实际 LVGL 字体逐字检查两套字体，保持缺字占位符开启。

```sh
python3 tools/snap_fonts.py --check
./tools/validate.sh --static
# 先激活 ESP-IDF 5.5.3：
./tools/validate.sh
```

IDF 构建已解析托管组件后，可运行真实 LVGL 桌面渲染／字形检查：

```sh
cmake -S tests/snap_preview -B build/preview-host -DCMAKE_BUILD_TYPE=Release
cmake --build build/preview-host -j 6
mkdir -p build/preview
build/preview-host/snap_preview build/preview
```

程序生成全部页面及错误样例的 PPM 截图，检查标签边界和两套字体的实际字形描述符，并使用 24 KB LVGL 池连续渲染 300 帧。它不模拟麦克风硬件、不验证 LCD 时序。应用层音频停止／确认、实际睡眠唤醒及 NVS 断电行为仍需设备验证；既有 BSP 故障测试覆盖音频芯片失败路径。

主机测试覆盖校准、十档力度、跳跃曲线、碰撞恢复、暂停、通关、纪录、音频预填／跳转／失败／结尾，以及时钟回退和停顿。全曲在 3–10 档、交替提前／准时／延后（−80/0/+80 ms）输入下均无伤通过；不输入则三次受伤结束。滤波后的纯音乐测试没有检测事件；混入 51 次合成响指检测到 51 次，断言要求召回至少 95% 且无额外事件。这不能代表真人响指准确率。共享门禁还检查 BSP 故障、字体、谱面一致性及合并固件布局。

## 设备验收与交付

构建、主机测试结果与准确产物身份在交付时报告。未经授权刷机并实际观察验收前，设备测试保持 NOT RUN。需检查：

1. 每个中文页面、错误状态、文字裁切、电量缺省及按键。
2. 安静环境下三强三弱校准，削顶／噪声／区间不足拒收，重启后校准保存。
3. 固定距离练习十档，观察响应延迟、轻响指漏检，以及说话、拍手、敲击、按键声误触发。

5. 持续采集与绘制时的可用／最低堆、最大连续块、任务栈、画面流畅度、闲置亮度和耗电。

仅将验证后的合并镜像 `build/FoloToy-AI-Passport-full.bin` 作为从 `0x0` 刷写的交付，保留匹配的内容寻址 ELF/MAP 归档。合并固件的填充覆盖 NVS，可能重置已有数据，包括校准和纪录。刷写必须明确授权；构建不会打开或写入 USB 端口。

### 连接设备观察

先经过授权刷入包含诊断流的新固件，再激活 ESP-IDF Python 环境：

```sh
python tools/snap_debug.py --list-ports
python tools/snap_debug.py --port /dev/cu.usbmodemXXXX
# 可选：仅将解析通过的诊断记录写入新文件，不覆盖旧记录。
python tools/snap_debug.py --port /dev/cu.usbmodemXXXX --record build/debug/session.jsonl
```

替换为枚举出的真实串口。USB 模式需要 `pyserial`，ESP-IDF Python 已提供它。
启动器不会自动选择串口，不发控制命令、不主动复位、不烧录；打开端口前将 DTR/RTS
置为未断言状态。操作系统／驱动的开口瞬态仍需本机实测。先关闭占用端口的 monitor。
断连时保留最后数据并提示停更，检查连接后重新启动工具。没有设备也能点击
“查看演示数据”检查曲线；它会明确标为合成演示，不能与真机串口同时开启。

固件默认启用 `CONFIG_SNAP_DEBUG_TELEMETRY`，可在 menuconfig 的 Snap Runner 菜单关闭；
交付门禁使用 `sdkconfig.defaults`，因此若要交付关闭版本，需在 defaults 中明确设置。
使用同一 USB 控制台输出 `@snap ` 前缀的 v1 JSON 行：

| 类型 | 频率／触发 | 数据 |
| --- | --- | --- |
| `audio` | 约 10 Hz | 100 ms 内最大峰值、末帧 RMS、噪声底、当前检测阶段 |
| `detect` | 每个完整候选声音窗口 | 瞬态接受、衰减不足或高频不足，以及窗口峰值 |
| `input` | 检测事件进入应用时 | 起跳、空中忽略、采集成功、削顶／噪声拒绝、保护间隔或过期 |
| `state` | 约 5 Hz（休眠期间停止） | 页面、校准值、档位、运行编号、距离、生命、跳高和障碍 |

事件时间单位为设备启动后的毫秒。音频和应用任务只向长度 8 的诊断队列非阻塞发送，
独立低优先级任务格式化并写 USB；队列满则丢弃诊断并累计 `dropped`，不等待 USB。
这不统计底层 USB 丢字节或游戏输入队列丢弃。诊断任务分配失败时游戏继续运行。
只传数值和事件，不传录音。面板保留最多 300 个音频点、80 条事件；旧版固件没有此协议。

通过 `--record` 保存的 JSONL 只允许写入被 Git 忽略的 `build/` 内新文件；普通串口日志不写入。
固件恢复启动后，明显回退的时间戳会清空图表，轻微跨任务乱序不会误判重启。
