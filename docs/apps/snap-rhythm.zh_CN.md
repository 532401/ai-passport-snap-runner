# 山妖洞穴音乐节奏分析

本分析替代此前按声学峰值筛选的谱面，针对[素材来源](../../assets/README.zh_CN.md)中记录的同一份 Musopen 录音，全长 154.091 秒。扬声器版本现已逐样本对齐地归一化响度，没有剪辑、变速、变调或新增 MP3 解码偏移；分析记录保留参考 PCM 哈希，全部节拍与尾声重音时间点不变。游戏使用逐拍时间点，不用固定 BPM 外推整首曲子。

| 录音段落 | 时间（秒） | 四分音符 BPM 范围 |
| --- | --- | --- |
| 引子延长音 | 0–4.38 | 不建立规则拍网 |
| 开头主题，乐谱第 2–25 小节 | 4.38–58.06 | 102.6–110.1 |
| 逐渐加速，第 26–41 小节 | 58.06–89.26 | 112.1–136.4 |
| 进入高潮，第 42–49 小节 | 89.26–101.98 | 142.9–160.0 |
| Più vivo，第 50–61 小节 | 101.98–118.80 | 160.0–179.1 |
| 末段加速，第 62–73 小节 | 118.80–134.00 | 180.5–201.7 |
| 尾声，含休止和孤立重音 | 134.00–154.091 | 独立重音时间点，不套固定 BPM |

范围按相邻小节线测得：`240000 / 小节时长（毫秒）`，不是相邻单拍的瞬时速度。分段用于概括录音的加速过程；Più vivo 入口也对应乐谱中的速度标记。

## 方法与边界

使用 [Beat This!](https://github.com/CPJKU/beat_this) 1.1.0 的 `final0`、`final1` 两个模型分析原始全频 FLAC。规则段拍点的模型差异不超过 20 ms。但模型原始的**小节强拍标签并不可靠**：部分位置会把其他拍标为第一拍，或中途改变相位。因此从 4.380 秒的 B 音主题入口（乐谱第 2 小节）开始按 4/4 连续计数，并参照[格里格公版钢琴谱](https://www.mutopiaproject.org/ftp/GriegE/O46/Dans_l_antre_du_roi_de_la_montagne/Dans_l_antre_du_roi_de_la_montagne-a4.pdf)核对结构。开头 F♯ 延长音、第 50 小节 Più vivo、尾声入口的四分休止符提供结构参照。没有把谱面印刷速度当作这份录音的实际 BPM。

119.130 秒后，两模型都转为半速计拍。缺失的四分拍取相邻已检测拍点的中点，保持此前的 4/4 相位，跟随局部加速。例如第 63 小节从 120.130 秒开始，而不是原始模型标出的 120.460 秒重音。这些插值拍点可信度较低。尾声有休止和落在其他拍上的重音，模型分歧较大，不外推小节线。改为在原始录音的短窗口中定位 8 次孤立管弦乐突起：取 40 ms RMS 增量最大处，使用 10 ms 窗口、5 ms 步长，以窗口中心计时。其中 **135.160、139.100、143.000、149.540 秒**用于起跳，其余因距上一次起跳过近而跳过。删除与第一个尾声重音冲突的 132.810 秒常规起跳点，保留 2.5 秒间隔下限。最后一下收束重音也安排了障碍。这些是独立声学重音，不能冒充小节第一拍，落点仍需试听验收。

这是结合乐谱结构校正的自动分析，**并非音乐专家逐拍听写**。模型时间分辨率为 20 ms。人工试听验收，特别是快速段插值位置，以及实际扬声器、显示、响指识别延迟，仍未验证。两模型一致不等于时间绝对准确。

## 固定数据与游戏规则

- [逐拍时间表](../../assets/music/mountain-king-beats.json)：289 个四分拍位置，包含不可玩的尾声边界；记录乐谱小节／拍号、插值标记、分段统计、音源及模型哈希和局限。独立的 `coda_accents` 列表记录 8 个孤立重音及其定位窗口。
- [游戏谱面](../../assets/music/mountain-king-chart.json)：39 个起跳点：35 个规则段小节第一拍，加 4 个独立尾声重音。开头几个位置为 4.380、9.000、13.480、17.920、22.340 秒。最小间隔仍为 2.5 秒，必要时跳过整个小节。不随机摆放；尾声重音同样遵守最小间隔。
- `main/snap_chart_data.h`：生成的固件表。障碍中心在预定起跳后 280 ms 到达角色。对齐音乐强拍或独立尾声重音的是**响指／起跳时刻**，不是障碍进入屏幕或碰撞的时刻。引子不放障碍。

```sh
python3 tools/snap_music_chart.py
python3 tools/snap_music_chart.py --check
python3 tests/test_snap_music_chart.py
python3 tools/snap_music_report.py
python3 tools/snap_debug.py
```

打开 `http://127.0.0.1:8765/rhythm/` 查看速度曲线、准确小节时间和按采样位置混入的提示音试听。轻提示音表示普通拍，清脆提示音表示小节第一拍或尾声重音，更高提示音表示选中的起跳。点击小节可从它之前一秒开始试听。全部时间点保存在 `build/music-analysis/beats.csv`；`clicks.wav` 只用于分析，不嵌入固件。报告由独立 HTML／CSS／JS 和嵌入的音频组成，无网络依赖。

若要重新运行模型，在独立的 Python 3.10+ 环境中安装 `beat-this==1.1.0`、SoundFile、NumPy、PyTorch，然后执行：

```sh
python tools/snap_music_analyze.py original.flac --model final0 --output build/music-analysis/final0.json
python tools/snap_music_analyze.py original.flac --model final1 --output build/music-analysis/final1.json
```

输出为未经核对的估计和原始 logits，刻意不直接替换已核对的拍表和固件谱面。先检查拍号、相位、半速计拍及休止。普通构建只需要固定拍表、谱面和 PCM，模型及机器学习依赖不会进入设备或 CI。本次实际分析复用了本地 PyTorch 2.8.0 和 Python 3.9，仅在隔离环境的 Beat This! 包中加入延迟类型注解，推理代码及权重未变。新环境应使用 Python 3.10+。
